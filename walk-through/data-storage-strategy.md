# 데이터 저장소 전략 및 고도화 가이드 (Data Storage Strategy)

본 문서는 `cabt_drl` 프로젝트의 현재 데이터 저장 및 읽기 구조(`dataStorageService.js`)를 정리하고, 향후 백만 개 이상의 대용량 OHLCV 데이터셋으로 확장할 때 적용할 **고도화 저장소 아키텍처 전략**을 기술한 가이드입니다.

---

## 1. 현재 데이터 저장 및 읽기 방식 요약

### 1.1. 파일 저장 방식 (`saveData`)
- **저장 포맷**: JSON 파일 (`data/[symbol]_[interval]_[count]bars.json`)
- **데이터 구조**:
  - `meta`: 심볼, 타임프레임, 캔들 수, 시작/종료 시간, 수집 미달 경고(`warning`, `isPartial`) 정보
  - `data`: OHLCV 캔들 객체 배열 (`[{ timestamp, open, high, low, close, volume, ... }, ...]`)
- **특징**: `fs.mkdir({ recursive: true })`로 저장소 유무를 자동 보장하며, `fs.writeFile`로 인코딩하여 저장.

### 1.2. 저장 목록 조회 방식 (`listDataFiles`)
- **조회 프로세스**:
  1. `fs.readdir(DATA_DIR)`을 통해 `.json` 파일 목록을 필터링.
  2. **`Promise.all` + `map(async ...)`**으로 모든 JSON 파일들의 상태(`fs.stat`)와 텍스트 내용(`fs.readFile`)을 병렬(Parallel)로 동시 실행.
  3. 각 파일의 `meta` 정보와 파일 크기, 수정 시각을 모아 목록 배열로 반환.

### 1.3. 현재 방식의 장점 및 적합성
- **직관성**: 사람이 에디터로 직접 데이터를 쉽게 열어볼 수 있음.
- **적합 규모**: 캔들 10만 개 이하(약 28 MB) 소규모~중규모 데이터셋에서는 `Promise.all` 병렬 처리로 0.1초 이내에 매우 빠르게 동작함.

---

## 2. 데이터 규모 확장에 따른 구조적 한계 분석

| 항목 | 소규모 데이터셋 (10만 개) | 대규모 데이터셋 (100만 개 이상) |
| :--- | :--- | :--- |
| **단일 파일 크기** | 약 28 MB | **약 280 MB ~ 300 MB** |
| **목록 조회 시 메모리** | 약 50 MB ~ 100 MB | **약 1.5 GB ~ 2 GB 이상 (메모리 폭발 위험)** |
| **파이썬 로딩 속도** | 약 0.1초 | **약 3초 ~ 5초 이상 (CPU 병목)** |

### ⚠️ 핵심 병목 지점
현재 구조는 단지 파일 목록(`listDataFiles`)을 띄우기 위해서도 300MB짜리 전체 JSON 파일을 메모리로 몽땅 읽어와 파싱해야 하므로, 파일이 수십 개 이상 쌓일 경우 **Node.js 서버 힙 메모리 과부하(OOM) 및 렉**이 발생할 수 있습니다.

---

## 3. 대용량 확장을 위한 향후 고도화/효율화 전략

데이터량이 백만 개 이상으로 커지는 시점(Phase 4 고도화 단계)에는 **"Parquet 바이너리 포맷 + 통합 메타 인덱스(`dataset_index.json`)"** 아키텍처로 전환합니다.

### 3.1. 고도화 디렉터리 및 저장 구조
```text
data/
├── dataset_index.json                        # [통합 메타 파일] 모든 데이터셋 목록 요약본 (0.5 KB)
├── btcusdt_1h_1000000bars_202401_202512.parquet # [실제 데이터 1] 100만 개 캔들 (압축 바이너리 ~15MB)
└── ethusdt_5m_500000bars_202501_202506.parquet  # [실제 데이터 2] 50만 개 캔들 (압축 바이너리 ~8MB)
```

### 3.2. 핵심 개선 요소 3가지

1. **Apache Parquet / Feather 포맷 도입 (90% 압축)**
   - 300MB JSON ➡️ **15MB Parquet 바이너리 파일로 획기적 압축**.
   - 파이썬 PyTorch / `pandas` 학습 환경에서 백만 개 데이터를 **0.05초 만에 메모리로 직행 로딩**.

2. **통합 메타 인덱스 파일 (`dataset_index.json`) 관리**
   - 데이터 저장 시 `dataset_index.json` 파일에 메타정보만 1줄 추가.
   - 목록 조회 시 대용량 데이터 파일에 접근하지 않고 **`dataset_index.json` 파일 1개만 읽어 0.001초 만에 화면에 목록 반환**.

3. **파일명 메타 인코딩 (이중 안전장치)**
   - 파일 이름 자체에 심볼, 타임프레임, 개수, 기간을 표기하여 인덱스 파일 손상 시에도 언제든 재복원(Rebuild) 가능하도록 보완.

---

## 4. 로드맵에 따른 전략 전환 시점
- **Phase 1 ~ 3 (현재 ~ GUI 연동 및 기초 백테스트)**: 현재의 **JSON 파일 방식**을 유지하여 직관적으로 시스템 구축.
- **Phase 4 (대용량 데이터 수집 및 PyTorch DRL 대규모 학습)**: 본 문서의 **Parquet + dataset_index.json** 구조로 고도화 전환.
