## 1. 지금까지의 경과 요약

### 출발점: RADE 시스템의 아쉬움

RADE(1시간봉, HMM 3-State, Calmar 16.08)는 훌륭하지만, 소액 자본(예: 100만 원)에서는 두 가지 문제가 있다:

- **절대 수익이 작다**: 연 37.8% 복리여도 100만 원 기준 연 38만 원.
- **거래가 너무 드물다**: 월 3~4회. 실전 검증에 수개월이 걸린다.

### 이미 시도해서 폐기된 방향

| 시도 | 결과 | 교훈 |
|:---|:---|:---|
| RADE 로직을 15분봉으로 축소 (`exp28`) | MDD 44%로 붕괴 | 추세 추종은 타임프레임이 짧을수록 노이즈에 취약 |
| 5분, 30분봉으로도 변경 | 짧을수록 악화 | 동일한 논리(돌파/추세)를 단순히 빠르게 돌리는 것은 해답이 아님 |
| 1H HMM 필터 + 15분봉 실행 | MDD 상승, 수익률 급감 | 하위 프레임 실행이 상위 필터의 이점을 상쇄함 |

**결론: "같은 접근법을 더 짧은 타임프레임에 적용하는 것"은 전부 실패했다.**
따라서 완전히 다른 종류의 엣지(Edge)를 찾아야 한다.

### 두 차례의 AI 대화에서 공통으로 도출된 방향

여러 모델에게 물어봐도 결론은 비슷했다:

> 차트의 "모양(패턴)"을 예측하는 대신, 코인 선물 시장의 **"구조적 수급 결함"**을 노려야 한다.

구체적으로 반복 추천된 후보는 3가지:
1. 청산(Liquidation) 데이터 기반 역발상
2. 펀딩비(Funding Rate) 극단값 역발상
3. 페어 트레이딩(Pair Trading, BTC vs ETH 스프레드)

단, 이 3가지 모두 **아직 한 번도 데이터로 검증하지 않은 가설 단계**이다.

## 2. 핵심 개념 상세 해설

OHLCV(시가/고가/저가/종가/거래량)와 달리, 위의 3가지 전략은 코인 선물 시장에만 존재하는 특수한 데이터를 활용한다.
각 개념을 OHLCV에 익숙한 트레이더의 관점에서 설명한다.

### 2-1. 펀딩비(Funding Rate)란?

**한 줄 요약**: 롱 포지션 보유자와 숏 포지션 보유자 사이에서 8시간마다 오가는 "수수료(벌금)"이다.

**왜 존재하는가?**
- 바이낸스의 BTCUSDT 선물은 만기일이 없는 "영구 계약(Perpetual)"이다.
- 만기일이 없으면 선물 가격이 현물 가격에서 괴리될 수 있다.
- 이를 막기 위해 바이낸스는 8시간마다(매일 01:00, 09:00, 17:00 KST) "펀딩비 정산"을 한다.

**작동 방식**:
```
[선물 가격 > 현물 가격] → 펀딩비 양수(+)
  → 롱 보유자가 숏 보유자에게 돈을 지불
  → "롱이 너무 많으니 줄여라"는 시장의 압력

[선물 가격 < 현물 가격] → 펀딩비 음수(-)
  → 숏 보유자가 롱 보유자에게 돈을 지불
  → "숏이 너무 많으니 줄여라"는 시장의 압력
```

**정상 범위 vs 극단값**:
- 정상: 약 +0.01% (연환산 약 10%). 아무 의미 없는 잔잔한 수준.
- 과열: +0.05% ~ +0.10% 이상 (연환산 50~100%+). 개미들이 롱에 미쳐있다는 신호.
- 극단적 음수: -0.05% 이하. 공포에 질려 숏이 과도하게 쌓인 상태.

**전략의 핵심 가설**:
- 펀딩비가 극단적 양수(+)일 때 → 시장은 "과열된 롱"으로 가득하다 → 세력은 이들을 청산시키기 위해 가격을 일시적으로 끌어내린다 → **숏으로 진입하면 유리하다**.
- 펀딩비가 극단적 음수(-)일 때 → 그 반대.

**데이터 접근성**:
- 바이낸스 REST API: `GET /fapi/v1/fundingRate` (과거 펀딩비 이력 조회 가능)
- 바이낸스 REST API: `GET /fapi/v1/premiumIndex` (현재 실시간 펀딩비 및 다음 정산 예정 펀딩비)
- 무료, 인증 불필요(공개 엔드포인트), 호출 제한도 넉넉함.

**냉정한 평가**:
- 장점: 데이터가 깔끔하고 확보가 쉬움. 로직이 단순하여 백테스트 구현이 빠름.
- 약점: "극단적" 펀딩비가 발생하는 빈도가 매우 낮다(연 5~15회 수준). 단독 전략으로는 거래 횟수 부족.

### 2-2. 청산(Liquidation)과 미결제약정(Open Interest)이란?

**한 줄 요약**: 레버리지를 쓴 트레이더의 담보금이 바닥나면 거래소가 강제로 포지션을 닫아버리는 것이 "청산(Liquidation)"이고, 현재 시장에 열려 있는 모든 포지션의 총량이 "미결제약정(Open Interest, OI)"이다.

**청산이 일어나는 과정 (예시)**:
```
1. 트레이더 A가 10x 레버리지로 BTC 롱 진입 (100만 원 증거금, 1000만 원 포지션)
2. BTC 가격이 약 10% 하락
3. 손실 = 1000만 원 × 10% = 100만 원 → 증거금 전액 소진
4. 바이낸스가 자동으로 A의 포지션을 "시장가 매도" → 이것이 강제 청산
5. 이 시장가 매도가 추가 하락 압력을 만들어 다른 롱들도 연쇄 청산 → 캐스케이드
```

**미결제약정(OI)이 알려주는 것**:
```
OI 높음 = 시장에 레버리지 포지션이 많이 쌓여 있다
         = 한쪽 방향으로 가격이 밀리면 대규모 청산이 터질 수 있는 "화약고" 상태

OI 급감 = 대규모 청산이 방금 일어났다
         = 연약한 손(약한 투자자)이 정리되었으므로 되돌림 가능성이 높아짐
```

**전략의 핵심 가설**:
- 가격이 급락 + 동시에 OI가 급감 + 긴 아래꼬리(Wick) 캔들 출현 → 롱 포지션 대량 청산이 발생한 직후
- 이 시점은 "팔 사람은 다 팔린(강제로 팔린)" 상태이므로, 단기적으로 되돌림(반등)이 올 확률이 높다
- **급락 직후 롱으로 진입하여, 짧은 되돌림만 먹고 나온다**

**데이터 접근성**:
- 바이낸스 REST API: `GET /fapi/v1/openInterest` (현재 OI)
- 바이낸스 REST API: `GET /futures/data/openInterestHist` (과거 OI 이력, 5분/15분/1시간 등)
- 바이낸스 WebSocket: `forceOrder` 스트림 (실시간 개별 청산 이벤트)
- 과거 청산 이벤트 이력(aggregate)은 바이낸스 공식 API로는 제공되지 않음. Coinglass 등 서드파티나 직접 WebSocket 수집 필요.

**냉정한 평가**:
- 장점: "강제 청산 후 되돌림"이라는 메커니즘 자체는 구조적으로 타당함. 레버리지가 존재하는 한 사라지지 않는 엣지.
- 약점:
  - 과거 **청산 이벤트 이력 데이터**를 직접 확보하기가 어려움(직접 수집하지 않는 한).
  - 단, OI 이력 데이터는 확보 가능하므로, **OI 급감 + 긴 꼬리 캔들**이라는 프록시(대리 지표)로 대체 검증이 가능함.
  - 실시간에서 "빔이 끝났는지 아직 진행 중인지" 판단하는 것이 어려움.

### 2-3. 페어 트레이딩(Pair Trading)이란?

**한 줄 요약**: 같이 움직이는 두 자산(예: BTC, ETH)의 "가격 차이(스프레드)"가 평소보다 벌어지면, 다시 좁아질 것에 베팅하는 전략.

**원리를 OHLCV 관점에서 설명**:
```
평소: BTC +3% 오르면 ETH도 +3~4% 오른다 (높은 상관관계)

어느 날: BTC +5% 올랐는데 ETH는 +1%만 올랐다
  → 스프레드(BTC 대비 ETH의 상대 가격)가 비정상적으로 벌어짐
  → "ETH가 뒤처져 있으니 곧 따라잡을 것이다" 또는 "BTC가 과도하게 올랐으니 내려올 것이다"

진입: ETH 롱 + BTC 숏 (동시)
청산: 스프레드가 평균으로 돌아올 때 양쪽 다 청산
```

**왜 "시장 중립(Market Neutral)"인가?**:
- BTC가 10% 폭락해도, ETH도 비슷하게 폭락하므로:
  - BTC 숏에서는 이익
  - ETH 롱에서는 손실
  - 순손익 ≈ 0 (스프레드 변화분만 남음)
- 즉, 시장 방향에 상관없이 **"두 자산의 상대적 관계"**에만 베팅하는 것.

**핵심 통계 개념 — 공적분(Cointegration)**:
- 단순 상관관계(Correlation)와 다름. 상관관계는 "같은 방향으로 움직이는가"이고, 공적분은 **"두 자산의 차이가 일정 범위 안에서 유지되는가"**이다.
- BTC와 ETH가 공적분 관계라면, 스프레드가 벌어져도 결국 평균으로 돌아온다는 통계적 보장이 있다.
- 공적분 검정은 `statsmodels` 라이브러리의 `coint()` 함수로 간단히 수행 가능.

**데이터 접근성**:
- 바이낸스 REST API에서 BTCUSDT, ETHUSDT의 과거 OHLCV를 각각 받으면 됨.
- 추가 특수 데이터 불필요. 기존 RADE 데이터 파이프라인을 거의 그대로 활용 가능.

**냉정한 평가**:
- 장점: 가장 학문적으로 탄탄하고, 데이터 확보가 가장 쉬우며, 시장 방향 리스크가 제거됨.
- 약점:
  - 스프레드의 변동폭 자체가 크지 않으므로 **소액에서의 절대 수익이 매우 작음**.
  - 공적분 관계가 일시적으로 깨지는 구간(알트 시즌, ETH 특정 이벤트)에서 큰 손실 가능.
  - 두 종목에 동시 포지션을 열어야 해서 증거금이 반으로 분산됨.

## 4. 다음 단계: 구체적 실행 계획

### Phase 0: 데이터 확보 (최우선, 예상 소요: 1~2일)

어떤 전략이든 데이터가 없으면 검증이 불가능하다. 먼저 다음 데이터를 확보한다:

**필수 데이터 (바이낸스 공개 API로 확보 가능)**:
1. BTCUSDT 선물 5분봉 OHLCV (최소 2년, 이상적으로 4년)
2. ETHUSDT 선물 5분봉 OHLCV (페어 트레이딩용)
3. 과거 펀딩비 이력 (`/fapi/v1/fundingRate`, 8시간 단위, 수년치 가능)
4. 과거 미결제약정(OI) 이력 (`/futures/data/openInterestHist`, 5분 단위)
5. 롱숏 비율 이력 (`/futures/data/globalLongShortAccountRatio`, 5분 단위)

**확보 불가 데이터 (대안 필요)**:
- 개별 청산 이벤트 이력: 바이낸스가 과거 데이터를 제공하지 않음.
- 대안: OI 급감 + 거래량 급증 + 긴 꼬리 캔들을 "청산 캐스케이드의 프록시"로 사용.

### Phase 1: 단순 통계 검증 (예상 소요: 1~2일)

코딩은 최소한으로 하고, 핵심 가설이 진짜인지 **숫자 하나**로 확인한다:

**검증 1 — 펀딩비 역발상 (가장 쉬움, 30분이면 가능)**:
```
질문: "펀딩비가 상위 5%(극단적 양수)일 때, 다음 8시간 동안 BTC 가격은 평균적으로 오르나 내리나?"

방법:
1. 과거 펀딩비 이력을 불러온다
2. 펀딩비를 크기순으로 정렬하여 상위 5%, 하위 5% 구간을 나눈다
3. 각 구간에서 "해당 펀딩비 정산 직후 8시간 수익률"의 평균과 중앙값을 계산한다
4. 정상 구간(중간 90%)의 수익률과 비교한다

기대 결과: 극단적 양수 펀딩비 후에는 수익률이 음수(하락), 극단적 음수 후에는 양수(상승)이면 엣지 존재.
만약 차이가 없거나 반대라면 → 이 전략은 폐기.
```

**검증 2 — 청산 프록시 역발상 (1~2시간)**:
```
질문: "5분봉에서 거래량이 평균의 3배 이상이면서 아래꼬리가 몸통의 2배 이상인 캔들 직후, 다음 30분~2시간 가격은 반등하는가?"

방법:
1. 5분봉 OHLCV 데이터를 불러온다
2. 각 캔들의 거래량 z-score와 꼬리/몸통 비율을 계산한다
3. 조건을 만족하는 캔들을 "청산 빔 후보"로 라벨링한다
4. 이 후보들 이후 30분, 1시간, 2시간 수익률의 분포를 구한다

기대 결과: 양의 수익률이 통계적으로 유의미하면 엣지 존재.
```

**검증 3 — 페어 트레이딩 기초 (1~2시간)**:
```
질문: "BTC와 ETH의 가격 비율(또는 로그 스프레드)은 공적분 관계인가? 스프레드가 2σ 벗어났을 때 회귀하는가?"

방법:
1. BTC, ETH 1시간봉 종가를 불러온다
2. statsmodels.tsa.stattools.coint() 로 공적분 검정을 수행한다
3. 스프레드(= log(BTC) - β × log(ETH))를 계산하고, z-score를 구한다
4. z-score가 ±2를 넘은 시점 이후 스프레드가 0으로 돌아오는 비율과 평균 소요 시간을 측정한다

기대 결과: 공적분 p-value < 0.05이고, 회귀 비율이 80% 이상이면 실행 가치 있음.
```
