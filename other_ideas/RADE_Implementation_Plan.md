## 2. 국면 탐지 모듈 상세

### 2.1 HMM (1차 — 핵심 엔진)

| 항목 | 값 |
|------|-----|
| 라이브러리 | `hmmlearn.GaussianHMM` |
| 은닉 상태 수 | 2 (횡보 / 추세) |
| 관측 벡터 | `[수익률, 변동성(ATR/Price), 거래량변화율]` |
| 학습 윈도우 | 최근 720봉 (약 30일) 슬라이딩 |
| 출력 | `P(추세)` = 0.0 ~ 1.0 |
| 재학습 주기 | 매 168봉 (1주일) 자동 |

### 2.2 ADX + Choppiness Index (2차 — 교차 검증)

```python
ci_norm  = normalize(choppiness_index, 30, 70)      # 0(추세)~1(횡보)
adx_norm = 1.0 - normalize(adx, 10, 40)             # 0(추세)~1(횡보)
rule_score = 0.5 * ci_norm + 0.5 * adx_norm         # 0(추세)~1(횡보)
```

### 2.3 결합 로직

```python
hmm_trend_prob = 1.0 - hmm_range_prob               # HMM의 추세 확률
rule_trend_prob = 1.0 - rule_score                   # 룰 기반 추세 스코어

# HMM과 룰이 일치하면 확신, 불일치하면 전이 구간
if abs(hmm_trend_prob - rule_trend_prob) < 0.25:
    regime_trend_prob = 0.6 * hmm_trend_prob + 0.4 * rule_trend_prob
else:
    regime_trend_prob = 0.5  # 전이 구간 → 양 엔진 동등 축소 운영
```

## 3. 국면 전환 처리 프로토콜

### 3.1 히스테리시스 (채터링 방지)

```
횡보 → 추세 진입: regime_trend_prob > 0.65
추세 → 횡보 복귀: regime_trend_prob < 0.35
0.35 ~ 0.65: 현재 국면 유지 (전환 없음)
```

### 3.2 전환 시 기존 포지션 처리

| 기존 포지션 상태 | 처리 |
|:---:|:---:|
| 이익 중 | 트레일링 스탑 타이트화 → 자연 청산 유도 |
| 손실 중 | 즉시 시장가 청산 |
| 전환 직후 | 새 엔진 3봉 쿨다운 (관망) |

### 3.3 포지션 크기 블렌딩

```python
mean_revert_size = base_position_size * (1.0 - regime_trend_prob)
trend_follow_size = base_position_size * regime_trend_prob
```

## 4. 매매 엔진 요약 (바이낸스 선물 — 롱/숏 양방향)

### 엔진 1: 평균회귀 (횡보장)

#### 롱 진입 조건
| 항목 | 규칙 |
|------|------|
| 진입 | BB 하단 터치 + RSI < 30 + 거래량 급증 → **롱** |
| 손절 | 진입가 대비 -0.5% ~ -0.8% (고정) |
| 1차 익절 | BB 중심선 도달 시 50% 청산 + 잔여 본전컷 이동 |
| 2차 익절 | BB 상단 도달 시 전량 청산 |

#### 숏 진입 조건
| 항목 | 규칙 |
|------|------|
| 진입 | BB 상단 터치 + RSI > 70 + 거래량 급증 → **숏** |
| 손절 | 진입가 대비 +0.5% ~ +0.8% (고정) |
| 1차 익절 | BB 중심선 도달 시 50% 청산 + 잔여 본전컷 이동 |
| 2차 익절 | BB 하단 도달 시 전량 청산 |

### 엔진 2: 추세추종 (추세장)

#### 롱 진입 조건
| 항목 | 규칙 |
|------|------|
| 진입 | 박스권 **상방 돌파** 확인 + ADX > 25 + 거래량 동반 → **롱** |
| 손절 | 돌파 캔들 시가 또는 직전 스윙 저점 |
| 익절 | ATR 기반 트레일링 스탑 (2×ATR) — 상방 무제한 |

#### 숏 진입 조건
| 항목 | 규칙 |
|------|------|
| 진입 | 박스권 **하방 이탈** 확인 + ADX > 25 + 거래량 동반 → **숏** |
| 손절 | 이탈 캔들 시가 또는 직전 스윙 고점 |
| 익절 | ATR 기반 트레일링 스탑 (2×ATR) — 하방 무제한 |

## 5. 리스크 관리 (선물 시장 특화)

```
1회 매매 최대 손실 = 총 자산의 1%
포지션 크기 = (자산 × 0.01) / (손절 폭(%) × 레버리지)
동시 포지션 = 최대 1개 (롱 또는 숏)
일일 최대 손실 = 총 자산의 3% → Kill Switch 발동
레버리지 = 최대 5x (초기 권장 2~3x)
```

### 선물 시장 추가 고려사항

| 항목 | 반영 방법 |
|------|----------|
| 펀딩비 (Funding Fee) | 8시간마다 발생 — 포지션 유지 시간이 길면 비용으로 누적, 백테스트에 반드시 반영 |
| 청산가 (Liquidation Price) | 레버리지에 따른 강제 청산선을 손절선보다 충분히 멀리 유지 |
| 마진 모드 | **격리 마진(Isolated Margin)** 사용 — 1포지션 손실이 전체 계좌에 전이되지 않도록 격리 |
| 수수료 구조 | VIP 0 기본: Maker 0.02% / Taker 0.05% — 백테스트는 Taker 기준으로 보수적 산정 |

### 수수료 절감 방법 (선택사항)

| 방법 | 할인율 | 적용 조건 |
|------|:------:|----------|
| BNB로 수수료 결제 | 10% | BNB 보유 + 설정에서 "Pay trading fees with BNB" 활성화 (자본 규모 무관) |
| 레퍼럴 코드 | 최대 20% | 계정 생성 시 입력 (기존 계정은 적용 불가) |
| 지정가(Maker) 주문 우선 | - | Taker(0.05%) 대신 Maker(0.02%) 수수료 적용 |

## 6. 구현 단계 (기존 프로젝트 구조 활용)

### Phase 1 — 데이터 + 국면 탐지 (Python)
```
python/
├── data/
│   └── binance_fetcher.py       # 바이낸스 1H OHLCV 수집기
├── regime/
│   ├── hmm_detector.py          # HMM 국면 분류기
│   ├── rule_indicators.py       # ADX, CI, BB 계산 및 정규화
│   └── regime_manager.py        # 결합 로직 + 히스테리시스 + 전환 프로토콜
└── utils/
    └── indicators.py            # 공통 기술적 지표 계산
```
- 과거 3년 1H 데이터로 HMM 학습 → 국면 레이블링 시각화 검증
- ADX/CI 교차검증 스코어와 HMM 출력 비교 분석

### Phase 2 — 매매 엔진 + 백테스터 (Python)
```
python/
├── engines/
│   ├── mean_reversion.py        # 평균회귀 엔진
│   └── trend_following.py       # 추세추종 엔진
├── risk/
│   └── position_manager.py      # 1% Risk, OCO, 트레일링, Kill Switch
└── backtest/
    └── simulator.py             # 수수료(0.1%)+슬리피지 반영 백테스터
```
- 각 엔진 개별 백테스트 → 국면별 성과 검증
- 듀얼 엔진 통합 백테스트 → Walk-Forward Optimization으로 파라미터 튜닝

### Phase 3 — GUI 시각화 (Node.js, 기존 인프라 활용)
```
routes/    → 백테스트 결과 API, 국면 데이터 API
services/  → Python 실행 제어, 결과 파싱
public/    → TradingView Charts에 국면 구간 오버레이 표시
```
- 차트에 횡보/추세 국면 구간 색상 표시
- 매매 시점, 손익, MDD 시각화

### Phase 4 — 실전 자동매매
```
python/
└── live/
    ├── live_runner.py           # 1H 정각 루프 + 바이낸스 주문 API
    └── monitor.py               # Telegram/Discord 알림 + Kill Switch
```

- 클라우드 서버(AWS Lightsail 등)로 이관 후 24시간 가동
